# 重设计的产出是一个 layout 内核插件，不是把所有界面重写一遍；核心插件由 dsh 自迭代长出来

- 日期 / agent：2026-08-18 / claude
- 我原来的理解：按 Synara 设计规范「重新设计桌面发行版」= 我手写全部界面——
  token、组件库、侧栏、会话面、Dock 三个面板、整窗设置、⌘K、Trajectory、
  模型设置页，一次性重写 `plugins/deepbuddy` 里 2900 行。已经开始按这个路子
  写 styles/geometry/icons。
- 用户实际要的：手写的**只有基础 layout 插件**（骨架几何 + 设计系统 + 座位合同）；
  其余「发行版维护的核心插件」让 dsh 在**创造模式里自迭代**产出，验收后收编。
  重设计的交付物是**一套能长东西的地基**，不是一堆画好的界面。
- 分歧根源：范围假设——我把「按规范重设计」默认成「交付成品界面」，
  用户要的是「交付生产界面的机制」。设计规范是**填充物的标准**，
  不是**我的工作清单**。
- 以后如何避免：这个仓库的一切都以「机制 > 成品」为先（宪章三环、
  `dbdy.*` 座位、创造模式闭环都是同一个取向）。凡涉及新界面/新功能，
  先问一句：**这件事该我写，还是该让发行版自己长出来？**
  判据是「它决定其他东西的位置吗」——决定位置的归 layout 手写，
  在框定位置里画画的一律走座位 + 创造模式。

## 落点

- 方案：[[2026-08-18-layout-kernel-and-self-iteration]]

  「创造模式卡在审批」那个遗留的解，自绘审批面不需要 P4b/P4c。
- 已按旧理解写下的三个文件（`styles.ts` token 层、`geometry.ts` 新几何、

  不属于被推翻的部分。
